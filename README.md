# Neuro D&D

Neuro D&D - это настольная ролевая игра на базе AI, разработанная с использованием Python, FastAPI и чистого HTML/CSS/JS. Проект разработан для локального запуска в Windows "из коробки".

## Архитектура

Проект имеет четкое разделение на три основных компонента:

-   **`server/`**: Бэкенд на FastAPI, обрабатывающий всю игровую логику, API-запросы и взаимодействие с AI (локальный сервис Qwen через Ollama API).
-   **`frontend/`**: Клиентская часть, написанная на чистом HTML/CSS/JavaScript. Это одностраничное приложение (SPA) для взаимодействия с игрой.
-   **`data/`**: Хранилище данных в формате JSON. Здесь содержатся профили пользователей, кампании, журналы и т.д.

## Быстрый старт (Windows)

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <repository-url>
    cd neuro-dnd
    ```

2.  **Настройка окружения:**
    Запустите `setup.bat`, чтобы создать виртуальное окружение и установить все необходимые зависимости.
    ```bash
    setup.bat
    ```
    После выполнения скрипта будет создан файл `.env` на основе `.env.example`. При необходимости отредактируйте параметры подключения к локальному сервису Qwen:
    ```ini
    QWEN_API_URL=http://100.126.92.69:11434/api/generate
    QWEN_TEXT_MODEL=qwen-text
    QWEN_IMAGE_MODEL=qwen-image
    QWEN_TIMEOUT=120.0
    ```

3.  **Запуск сервера:**
    Запустите `run_dev.bat`, чтобы активировать виртуальное окружение и запустить веб-сервер.
    ```bash
    run_dev.bat
    ```
    Сервер будет доступен по адресу `http://localhost:8000`. Он также будет доступен с других устройств в вашей локальной сети по вашему локальному IP-адресу (например, `http://192.168.1.10:8000`).

4.  **Начало игры:**
    Откройте `http://localhost:8000` в вашем браузере. Зарегистрируйтесь и начните свою первую кампанию!

## Распределение ролей

Проект разработан командой из 4 человек. **Роль 2 — тимлид**, поэтому имеет меньшую техническую нагрузку.

### 🎮 **Роль 1: Game Logic & AI Integration Developer**
**Ответственность:**
- Разработка игровой механики D&D (система боя, проверки характеристик, инвентарь)
- Интеграция с локальной нейросетью (API для генерации текста DM-мастера)
- Реализация логики кампаний и квестов
- Обработка игровых событий и состояний
- **Галерея сгенерированных изображений** (UI компонент для просмотра всех картинок кампании)

**Основные файлы:**
- `server/game_logic/` — игровые механики
- `server/ai/dm_handler.py` — взаимодействие с AI DM
- `server/api/game_routes.py` — игровые endpoints
- `frontend/js/components/image_gallery.js` — галерея картинок

---

### 🖼️ **Роль 2: Team Lead & AI Image Generator Developer** ⭐
**Что делаешь простыми словами:**
- Пишешь код, который говорит локальной нейросети "нарисуй орка" или "нарисуй тёмный лес"
- Делаешь API endpoint'ы, чтобы фронтенд мог запросить картинку
- **Координируешь работу команды** (код-ревью, планирование, интеграция между ролями)

**Примеры задач:**
- Игрок входит в пещеру → фронтенд шлёт запрос → твой код генерит картинку пещеры через AI
- DM говорит "перед вами гоблин" → твой код генерит картинку гоблина и отдаёт её
- Смотришь за тем, чтобы все части проекта работали вместе

**Основные файлы:**
- `server/ai/image_generator.py` — связь с локальной нейросетью для картинок
- `server/api/image_routes.py` — endpoints типа `/generate-enemy` или `/get-location-image`

---

### 💻 **Роль 3: Frontend & User Interface Developer**
**Ответственность:**
- Разработка пользовательского интерфейса игры
- Реализация чата с DM-мастером
- Отображение игровых данных (карточки персонажей, инвентарь, карты)
- Интеграция с backend API
- Адаптивный дизайн и UX
- **Отображение сгенерированных картинок в игре** (враги, локации, декорации)

**Основные файлы:**
- `frontend/index.html` — основная структура
- `frontend/js/game.js` — игровая логика на клиенте
- `frontend/js/api.js` — взаимодействие с backend
- `frontend/css/` — стили интерфейса
- `frontend/js/components/` — UI компоненты
- `frontend/js/image_display.js` — показ картинок от AI

---

### 🔧 **Роль 4: Backend Infrastructure & Data Management Developer**
**Ответственность:**
- Архитектура FastAPI сервера и роутинг
- Система аутентификации и управления пользователями
- Работа с JSON базой данных (профили, кампании, сохранения)
- Настройка окружения и деплой скриптов
- Обработка ошибок и логирование
- **Сохранение и кэширование сгенерированных картинок** (чтобы одно и то же не генерилось дважды)

**Основные файлы:**
- `server/main.py` — точка входа FastAPI
- `server/auth/` — аутентификация
- `server/database/` — работа с данными
- `data/` — структура данных (включая `data/images/`)
- `setup.bat`, `run_dev.bat` — скрипты развертывания
- `server/utils/logger.py` — система логирования
- `server/utils/image_cache.py` — кэш картинок

---

## Принципы командной работы

- Каждая роль имеет четкую зону ответственности без пересечений
- Взаимодействие между ролями происходит через API контракты
- Тестирование проводится вручную каждым разработчиком в своей зоне
- Коммиты делаются в отдельные ветки с префиксами: `game/`, `images/`, `frontend/`, `backend/`
